Personal Website: Code Improvements 🌐

I implemented code generation using the Tygo tool.

My client and server are written in different programming languages: TypeScript and Golang. Previously, the code for structures passed between the client and server had to be manually written in both languages. Added a new field? You had to write it in two files: .go + .ts.

Now, Golang is the source of truth, and the TypeScript files are generated automatically during every build. An example is shown in the screenshot.

Previously, I thought it would be convenient to integrate a full-scale large REST framework into the project so that not only the common structures but also the entire REST client would be generated automatically. Instead, I’ve implemented this intermediate solution. Was it worth it? 🤔💭 Or would it be easier to just switch to a large REST framework right away? The main advantage of the intermediate approach is that there are fewer dependencies in the project. Yes, a code generator is also a dependency, but it’s small. It sort of sits on the side rather than permeating the entire project.
